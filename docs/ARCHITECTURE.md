# Personal Intelligence & Automation Agent (Telegram Bot) - Architecture & System Design

## 1. System Overview & Objective
The Personal Intelligence & Automation Agent is a private, 24/7 background intelligence and news synthesis service written in Node.js. It operates as a persistent daemon process using Long Polling against the Telegram Bot API.

The system gathers raw content from authoritative open feeds (Google News RSS, Reddit API) across multiple user-defined topics, normalizes and dedupes the data into a MySQL data lake, delegates analytical summarization to Google Gemini (`gemini-2.5-flash`), and formats structured HTML intelligence reports delivered strictly to an authenticated single user on Telegram.

## 3. Core Architectural Principles & Technical Constraints

### 3.1. Single-User Security Isolation (Admin Lock)
* **Rule:** The bot is private. Every incoming Telegram update (`message`, `callback_query`) passes through a mandatory global middleware.
* **Mechanism:** If `ctx.chat.id.toString() !== process.env.ADMIN_CHAT_ID.toString()`, the bot immediately halts execution with an unauthorized message and does not enter any conversation or trigger any state changes.

### 3.2. Mandatory Timezone Handling (`Asia/Ho_Chi_Minh` / UTC+7)
* **Problem:** Server dates in UTC drift between 00:00 and 06:59 UTC relative to Vietnam (07:00–13:59 VN time). Using `new Date().toISOString().split('T')[0]` causes date mismatches for morning shifts.
* **Solution:** All internal scheduling calculations, current-day evaluations, and digest lookups MUST use `Intl.DateTimeFormat` configured with `{ timeZone: "Asia/Ho_Chi_Minh" }`.
* **Day-of-Week Mapping:**
  * Monday = `1`, Tuesday = `2`, ..., Sunday = `7`.
  * Sunday is normalized from index `0` to `7` to match human convention.

### 3.3. HTML Formatting vs. Telegram Markdown
* **Rule:** NEVER use Telegram `parse_mode: "Markdown"` or `MarkdownV2` for AI-generated dynamic text. Gemini outputs characters (`_`, `*`, `[`, `]`, `(`, `)`, `~`, `` ` ``, `>`, `#`, `+`, `-`, `=`, `|`, `{`, `}`, `.`, `!`) that cause Telegram's Markdown parser to reject the entire payload with HTTP 400.
* **Mechanism:** All messages MUST use `parse_mode: "HTML"`. All dynamic text extracted from articles or generated by Gemini must be sanitized through an entity escaper:
  * `&` $\rightarrow$ `&amp;`
  * `<` $\rightarrow$ `&lt;`
  * `>` $\rightarrow$ `&gt;`

### 3.4. Rate-Limiting & Telegram Delivery Safety
* **Chunk Boundary Limit:** Telegram hard limit is 4,096 UTF-8 characters. The internal chunking engine caps pages at $\le 3,500$ characters to leave safety margins for headers and pagination tags.
* **Delay Throttling:**
  * Minimum **1,000 ms** delay between sequential chunk deliveries (`Part 1/2` $\rightarrow$ `Part 2/2`).
  * Minimum **1,500 ms** delay between different topics.
* **HTTP 429 Protection:** Every Telegram API call is wrapped in a dedicated `try/catch`. If an HTTP 429 error occurs, inspect `error.parameters.retry_after`, wait `retry_after * 1000` ms, and retry safely.

## 4. Execution Loops & Background Pipelines

```
                             [24/7 BACKGROUND ENGINE]
                                        │
    ┌───────────────────────────────────┼───────────────────────────────────┐
    │ (Every 30 Mins)                   │ (Minute 00 of Hour H)             │ (Minute 00 of Hour H)
    ▼                                   ▼                                   ▼
[1. INGEST JOB]                    [2. SYNTHESIZE JOB]                 [3. DISPATCH JOB]
  - Query Active Topics              - Concurrency Lock: isSynthesizing  - Query Unsent Digests
  - Scrape Google News RSS & Reddit  - Target Shift: Hour (H + 1)         - Target Hour: <= H && >= H-2
  - Deduplicate & Save raw_articles  - Filter: pub_date > last_delivery  - Chunk HTML into Pages (<=3500)
                                     - Gemini Structured JSON API        - Sequential Dispatch (1s delay)
                                     - Save into shift_digests           - Mark is_sent = 1
                                     - Error alert to Telegram           - Update last_delivered_at
```

---

### Pipeline 1: Raw Content Ingest (`ingestJob`)
* **Cadence:** Runs every 30 minutes (`*/30 * * * *`).
* **Workflow:**
  1. Fetch all distinct active topics from `subscriptions` where `is_active = 1`.
  2. For each normalized topic (`trim().toLowerCase()`):
     * Query Google News RSS search: `https://news.google.com/rss/search?q={topic}&hl=en-US&gl=US&ceid=US:en`.
     * If the topic matches developer/tech keywords (e.g., `dotnet`, `node`, `ai`, `python`, `code`), query Reddit Search JSON: `https://www.reddit.com/search.json?q={topic}&sort=hot&limit=10`.
     * Parse items using `cheerio`.
     * Execute `INSERT IGNORE` into `raw_articles`. Duplicate `(topic, link)` entries are silently ignored by MySQL's unique index.
     * Throttle 2,000 ms between topics to avoid source IP throttling.

---

### Pipeline 2: Pre-Shift AI Synthesis (`synthesizeJob`)
* **Cadence:** Runs at minute 00 of every hour (`0 * * * *`).
* **Target Delivery Window:** Prepares digests for the upcoming hour:
  $$\text{target\_hour} = (H_{\text{current}} + 1) \pmod{24}$$
* **Concurrency Guard:** Guarded by an in-memory boolean flag `isSynthesizing`. If a prior synthesis cycle is still active, subsequent runs exit immediately to avoid duplicate Gemini API calls.
* **Workflow:**
  1. Determine current Vietnam date string (`YYYY-MM-DD`) and Day of Week (1–7).
  2. Query `subscriptions` matching:
     * `delivery_hour = target_hour`
     * `is_active = 1`
     * `(schedule_type = 'recurring' AND days_of_week CONTAINS current_dow) OR (schedule_type = 'specific_date' AND specific_date = current_date)`
  3. For each qualified subscription:
     * Retrieve articles from `raw_articles` where:
       $$\text{pub\_date} > \text{COALESCE}(\text{last\_delivered\_at}, \text{NOW}() - \text{INTERVAL 24 HOUR})$$
       *(Guarantees that articles already sent in earlier shifts are never re-synthesized).*
     * If zero articles are found, prepare a structured empty-state JSON indicating no major events occurred in this window.
     * Invoke Gemini with strict JSON Schema output.
     * Attempt Gemini call with 1 auto-retry on failure. If still failing, dispatch an immediate operational alert to the admin's Telegram chat:
       `⚠️ [System Alert] Synthesis failed for topic "${topic}" (Shift ${nextHour}:00): ${error.message}`.
     * On success, persist structured JSON into `shift_digests` using `INSERT ... ON DUPLICATE KEY UPDATE` on `(subscription_id, delivery_date, delivery_hour)`.

---

### Pipeline 3: Timed Message Dispatch (`dispatchJob`)
* **Cadence:** Runs at minute 00 of every hour (`0 * * * *`).
* **Target Records:** Queries `shift_digests` matching:
  * `delivery_date = current_vietnam_date`
  * `is_sent = 0`
  * Delivery hour criteria with backward recovery grace window:
    $$\text{delivery\_hour} \le H_{\text{current}} \quad \text{AND} \quad \text{delivery\_hour} \ge (H_{\text{current}} - 2)$$
    *(Ensures missed shifts due to minor server restarts are recovered, while preventing stale floods if the host was down for multiple days).*
* **Workflow:**
  1. Parse stored `summary_json`.
  2. Execute **Event-Aware Smart Chunking**:
     * Header layout: `🔔 <b>BẢN TIN (${hour}:00) | ${TOPIC}</b> (${part}/${total})`.
     * Overview section placed exclusively on Page 1.
     * Event blocks appended sequentially until approaching 3,500 characters.
     * Clean cutoffs on event boundaries; fallback sub-chunking on paragraph breaks (`\n\n`) if a single event exceeds limit.
  3. For each generated page:
     * Send via `bot.api.sendMessage` with `parse_mode: "HTML"`, `disable_web_page_preview: true`.
     * Sleep 1,000 ms.
  4. Post-delivery database mutations:
     * Set `is_sent = 1` in `shift_digests`.
     * Update `subscriptions.last_delivered_at = NOW()`.
     * If `schedule_type == 'specific_date'`, set `is_active = 0` to auto-archive one-time events.
  5. Sleep 1,500 ms before processing the next digest.

---

### Pipeline 4: Automated Data Retention (`housekeepingJob`)
* **Cadence:** Runs daily at 03:00 AM VN time (`0 3 * * *`).
* **Action:**
  ```sql
  DELETE FROM raw_articles WHERE created_at < NOW() - INTERVAL 3 DAY;
  ```
* **Rationale:** Keeps MySQL storage footprint minimal, eliminates index bloat, and stays well within low-spec hosting bounds.

## 5. Structured AI Contract (Gemini Prompt Engine)

### 5.1. Prompt Architecture
The prompt is divided into two distinct logical tiers:
1. **Immutable System Core:** Contains strict anti-hallucination guardrails, brevity rules for sparse feeds, and output schema constraints.
2. **Dynamic Domain Guidance (`topic_guidance`):** Custom user instructions configured per topic (e.g., football tactics/transfers vs. tech API benchmarks vs. macroeconomic financial shifts).

### 5.2. Core Guardrail Rules
* **Strict Evidence Grounding:** Only synthesize facts, metrics, and entities explicitly documented in the input payload. If technical metrics (ms, MB, percentages) are absent, the model MUST NOT fabricate them.
* **Anti-Fluff Directive:** If a shift has minimal signal, output 1 concise event rather than expanding into multiple verbose bullet points.
* **JSON Schema Guarantee:** The response MIME type is strictly `application/json` matching this schema:

```json
{
  "type": "OBJECT",
  "properties": {
    "overview": { "type": "STRING", "description": "Concise 1-2 sentence executive summary of the shift." },
    "events": {
      "type": "ARRAY",
      "items": {
        "type": "OBJECT",
        "properties": {
          "title": { "type": "STRING", "description": "Clear, concise headline of the event." },
          "details": { "type": "STRING", "description": "Core mechanics, factual progression, and context." },
          "impact": { "type": "STRING", "description": "Consequences, actionable takeaways, or developer implications." },
          "sources": {
            "type": "ARRAY",
            "items": { "type": "STRING" },
            "description": "Original source URLs matching this event from input data."
          }
        },
        "required": ["title", "details", "impact", "sources"]
      }
    }
  },
  "required": ["overview", "events"]
}
```

## 6. Telegram User Interface & Interaction State Machine

The bot provides two primary operation modes via `grammY`:

### 6.1. On-Demand Instant Research Flow (`/start` $\rightarrow$ `[⚡ Cào tức thì]`)
* User triggers conversation $\rightarrow$ inputs arbitrary keyword or query.
* Real-time scrape triggers against Google News RSS & Reddit.
* Fetched articles pass directly to Gemini $\rightarrow$ immediate HTML rendering.
* Results delivered back to the chat instantly, bypassing the shift queue.

### 6.2. Subscription Management Flow (`/start` $\rightarrow$ `[➕ Thêm lịch]`, `[📋 Danh sách]`)
* **Create Subscription Conversation:**
  1. Prompt for topic keyword (auto-normalized to `trim().toLowerCase()`).
  2. Optional topic-specific analysis guidance.
  3. Prompt for shift hour (integer `0`–`23`).
  4. Select recurring days (Everyday, Workdays, Weekends) or specific date (`YYYY-MM-DD`).
* **Management Dashboard:**
  * Inline keyboard listing active subscriptions.
  * One-tap toggle active/inactive status.
  * One-tap delete with cascade removal of pending unfulfilled digests.
